## 一、今天要回答的问题：28 天里最大的一个认知改变是什么？

**一句话：我学会了「在资源约束下，砍掉不必要的东西，比什么都做更重要」。**

28 天前，PRD 里写的是一台「重机器」：Three.js 3D 场景 + WebGPU + 本地下载 1~2GB 的 AI 模型 + 拖拽旋转缩放搭建。到第 2 周快结束时，现实开始说话——低配设备跑不动 3D、本地模型下载慢、手机端完全没法玩、素材版权又是天坑。

于是我做了一个贯穿全程的决定：**把「AI 凭空造物」降级成「词典识词 + 预制素材变体」，把 3D 降级成 Canvas 2.5D，把本地大模型换成 CloudBase 云函数后端。**

这不是退缩，是止损。做产品最贵的不是写代码，是把力气花在「用户永远用不到」的功能上。**先让核心循环（输入英文 → 世界里出现东西 → 能保存）跑通、可公开访问，再谈锦上添花**——这个排序意识，是我 28 天里最大的认知改变。

它改变了我的三个默认动作：
1. 遇到「做不做」先问「不做会不会影响核心闭环」，而不是「这个很酷」。
2. 验收标准要跟着产品形态一起变，而不是死守第一天写的清单。
3. 每一份文档、每一个 commit，都要能「当场打开给你看」，而不是「理论上应该行」。

## 五、板块 ④：结营复盘（三件事 + 反思）

**三件事：**
1. **问题消失**：从「3D 跑不动、模型下不动、手机不能玩」到「2.5D 低算力、词典秒出、手机可玩、公网可访问」——最痛的技术债通过「降级」清零。
2. **功能可用**：核心循环（输入英文 → 造物 → 保存 → 公网持久化）完整跑通，云函数 CRUD 全闭环，错误提示中文化。
3. **无溢出**：严守「当天清单唯一范围」，未加范围外功能；文档、commit、Skill 都按约定落位。

**反思问题（AI 先答）：**
> 28 天里最容易被忽视的「页面状态」是什么？
> **答：公网部署态 vs 本地开发态的割裂。** 本地 `localhost:5174` 跑得好，不等于公网正常——静态托管无 SPA 回退（`/editor` 直达 404）、dist 的 index 与 assets 是否同层、云函数是否真的部署成功，本地全看不见。所以验收第一动作永远是「先打公网首页 + 健康接口 + 线上写入刷新」，而不是看代码。

**给未来（回补闸门）的三条：**
1. 先补**导出/导入**（唯一大缺口，P0 里最影响「作品可带走」的一项）。
2. 补**离开确认 + 清空二次确认**（低成本，补完异常体验）。
3. 有富余再补**分类筛选交互**和**帮助页完整内容**。
